# Student Performance Analytics & Early Warning System

A beginner-friendly Python mini-project for analyzing a class's marks and attendance. It reads a CSV dataset, prints a terminal dashboard, identifies students who may benefit from support, suggests practical next steps, and saves a detailed CSV report.

## Features

- Four-subject totals, averages, and grades.
- Pass/fail outcome: a student passes only when every subject mark is at least 40.
- Attendance monitoring, with below 75% treated as a follow-up flag.
- Weakest-subject detection and subject-wise class averages.
- Top five performers among students who pass all subjects.
- Early-warning alerts and simple personalized study suggestions.
- A reusable analysis function and generated report at `reports/student_performance_report.csv`.
- A responsive, static browser dashboard at `reports/student_dashboard.html` (no web server or web framework required).
- Expandable fictional student academic profiles, subject lecturer/class-average cards, attendance bands and alerts, grade distribution, a five-day study rhythm, invitations/fest listings, campus community ideas, study prompts, and complete marks records.
- A distinctive layered background, responsive cards, and extra class-insight sections make it suitable for a mini-project presentation.
- Sample campus calendar and lecturer names are fictional presentation data; the student profile intentionally excludes login credentials and private contact details.
- Included sample dataset with 30 fictional students.

## Requirements

- Python 3.10 or newer
- NumPy and Pandas (listed in `requirements.txt`)
- Python, NumPy, and Pandas handle the analytics. The browser report is static HTML/CSS generated by Python; there is no JavaScript, web framework, or browser package.

## Run the project

From the project root, create and activate a virtual environment, then install dependencies:

```text
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Run the analysis to print the terminal dashboard and generate both CSV and browser-viewable HTML reports:

```text
python main.py
```

Use a different input or report path if needed:

```text
python main.py --input data/students.csv --output reports/my_class_report.csv
```

Run the automated checks:

```text
python -m unittest discover -s tests -v
```

## Project files

- `main.py` — validated input, analysis functions, terminal dashboard, static HTML/CSS portal generator, and CSV export.
- `reports/student_dashboard.html` — generated class dashboard; open this file in a browser to view the website-style output.
- `data/students.csv` — fictional sample student records; edit marks and attendance here.
- `tests/test_main.py` — basic checks for grades, pass rules, alerts, and sample input.
- `docs/PROJECT_GUIDE.md` — step-by-step explanation, customization guidance, presentation outline, and viva questions.
- `requirements.txt` — project dependencies.

## Customize the rules

At the top of `main.py`, change `PASS_MARK`, `LOW_ATTENDANCE_LIMIT`, `LOW_AVERAGE_LIMIT`, or `SUBJECTS`. If you change the subject list, add matching mark columns to the CSV. Update the grade boundaries in `calculate_grade()` if your institution uses a different scheme.

## GitHub setup

1. Create a new empty repository on GitHub (do not add a README there if you already have this one locally).
2. In this project folder, initialize Git, stage, and commit:

	```text
	git init
	git add .
	git commit -m "Add student performance analytics mini-project"
	```

3. Replace `<your-repository-url>` with the URL shown by GitHub, then connect and push:

	```text
	git remote add origin <your-repository-url>
	git branch -M main
	git push -u origin main
	```

4. Keep real student-identifying data private. The included sample data is fictional; do not publish personal educational records.

See the project guide for a detailed explanation and presentation notes.

## Publish the dashboard with GitHub Pages

The repository includes a root `index.html` that opens the generated dashboard. After the project is pushed to GitHub, open the repository's **Settings → Pages**, choose **Deploy from a branch**, select `main` and `/(root)`, then save. GitHub will show the public Pages URL in that section after deployment finishes. Pages serves the static HTML/CSS report; it does not run the Python analysis. To publish updated data or calculations, regenerate the dashboard with `python main.py` and push the updated files.
